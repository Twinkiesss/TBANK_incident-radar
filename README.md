# Incident Radar

CLI-утилита для анализа NGINX-логов: читает логи (файлы, glob-маски или URL),
разбирает строки, фильтрует по датам и строит отчёт со статистикой.

Одна строка лога выглядит так:

```text
93.180.71.3 - - [17/May/2015:08:05:32 +0000] "GET /downloads/product_1 HTTP/1.1" 304 0 "-" "Debian APT-HTTP/1.3"
```

Из неё утилита достаёт IP, дату, метод, ресурс, протокол, код ответа и размер
ответа. Из миллиона строк собирает картину: сколько запросов, какие endpoint'ы
популярны, сколько ошибок, какие ответы самые тяжёлые.

## Статус

- [x] **MR1** — CLI и источники логов
- [x] **MR2** — парсер и статистика

## Аргументы CLI

```text
--path, -p             файл, glob-маска или URL (обязателен)
--output-format, -f    json или markdown (по умолчанию markdown)
--output-path, -o      путь для отчёта
--from / --to          границы периода включительно (yyyy-MM-dd)
--help, -h             справка
--version, -V          версия
```

Поддерживаемые расширения входных файлов: `.log`, `.txt`.

### Примеры

```bash
# Один файл
./gradlew run --args="--path samples/logs/access-2025-03-01.log"

# Оба файла по маске (в PowerShell маску обязательно брать в кавычки)
./gradlew run --args="--path 'samples/logs/access-*.log'"

# С фильтром по датам
./gradlew run --args="--path samples/logs/access-2025-03-01.log --from 2025-03-01 --to 2025-03-01"
```

## Что работает

### Источники (MR1)

- **Локальный файл** — `--path samples/logs/access-2025-03-01.log`.
- **Glob-маска** — `--path "samples/logs/access-*.log"`. В PowerShell и CMD маску
  нужно брать в кавычки, иначе оболочка раскроет `*` сама и передаст несколько
  аргументов.
- **URL** — `--path http://127.0.0.1:8000/access-2025-03-01.log`. Чтение
  потоковое через `HttpResponse.BodyHandlers.ofInputStream()`.

### Парсер (MR2)

Строка разбирается регулярным выражением по формату NGINX combined log.
Метод, ресурс и протокол из `"GET /downloads/product_1 HTTP/1.1"` — **три
отдельных поля** модели `LogRecord`. Битая строка (не совпала с форматом,
непарсящаяся дата, отрицательный размер, кривой код) — **не роняет программу**:
пишется `WARN: skipped malformed log line` в stderr, строка пропускается.

### Фильтр по датам (MR2)

- заданы обе границы — период **включительно**;
- задана одна — открытая граница с другой стороны;
- не задана ни одна — все записи.

### Статистика (MR2)

- общее число запросов;
- распределение кодов ответа (по возрастанию кода);
- top-10 ресурсов (по убыванию количества, при равенстве — по алфавиту);
- размер ответа — average / max / p95. Дробные значения округляются до 2 знаков
  после запятой.

### p95 — nearest rank

Выбран метод **nearest rank**: `index = ceil(0.95 * n) - 1` на отсортированном
массиве размеров. На сэмплах проекта это даёт `5450` (целое число). Линейная
интерполяция дала бы `5450.20`. Оба метода корректны; nearest rank выбран,
потому что всегда возвращает наблюдённое значение и не изобретает число между
измерениями. Именно из-за этой неоднозначности цифры p95 у разных систем
мониторинга не сходятся.

## Коды возврата

```text
0 -> успех
1 -> непредвиденная ошибка
2 -> некорректное использование
```

Код `2` возвращается при:

- не передан `--path`;
- файла нет или это не regular file;
- расширение файла не `.log` / `.txt`;
- URL вернул не `200`;
- glob ни с чем не совпал;
- `--output-format` не `json` и не `markdown`;
- `--from >= --to`;
- `--output-path` уже существует;
- расширение `--output-path` не соответствует формату (`.md` для markdown,
  `.json` для json).

Непредвиденные `RuntimeException` пробрасываются наружу — picocli возвращает `1`.

## Потоковость

Файлы читаются через `Files.newBufferedReader()`, URL — через
`HttpResponse.BodyHandlers.ofInputStream()`. Никакого `Files.readAllLines()`:
гигабайтный лог не кладёт процесс в память на этапе чтения.

## Как проверить

### Тесты

```bash
# Windows PowerShell
.\gradlew.bat test --tests "academy.incidentradar.mandatory.mr1.*"
.\gradlew.bat test --tests "academy.incidentradar.mandatory.mr2.*"
```

Ожидаемо:

- MR1 — **11 passed** (5 в `CliValidationTest` + 4 в `LogSourceTest` +
  2 параметризованных прогона `@ValueSource`);
- MR2 — **12 passed** (`DateFilterTest` × 4, `LogParsingTest` × 3,

## Принятые решения

- **Стандартная библиотека вместо Lombok.** Lombok нет в
  `gradle/libs.versions.toml`, а HELP.md запрещает добавлять библиотеки без
  согласования с ментором. Модели на records перекрывают те же задачи без
  зависимостей.
- **picocli для CLI.** `--help`, `--version`, `ParameterException` → exit code
  `2` из коробки.
- **`CliException` → `ParameterException`.** Доменные ошибки (файл не найден,
  404, `from >= to`, output уже существует) оборачиваются в
  `ParameterException`, picocli возвращает `2`.
- **NullAway + JSpecify.** Все поля picocli-команды помечены `@Nullable`, потому
  что заполняются рефлексией. Аргументы перед использованием разворачиваются
  через `requireNonNull(...)`. В `DateFilter` обе границы `@Nullable`.
- **Потоковое чтение.** `Files.newBufferedReader()` для файлов,
  `HttpResponse.BodyHandlers.ofInputStream()` + `BufferedReader` для URL.
- **Glob.** Базовая директория вычисляется из префикса до первого `*`/`?`,
  обход — `Files.walk(base, 1)`, фильтр по расширению. Пустой результат —
  ошибка `2`.
- **p95 — nearest rank.** Обоснование — в разделе «p95».
